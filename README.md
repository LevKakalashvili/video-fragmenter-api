# Video Fragmenter Service (Сервис фрагментации видео файлов)

Микросервис предназначен для **высокопроизводительного разбиения
видеофайлов на чанки** с последующей загрузкой чанков в S3‑совместимое
хранилище и публикацией прогресса обработки в Kafka.

Основная цель MVP --- **максимальная производительность обработки** при
сохранении расширяемой архитектуры.

------------------------------------------------------------------------

# 1. Основные требования

## Функциональные

Сервис должен:

1.  Получать задачи на обработку из **Kafka**
2.  Загружать исходный видеофайл из **S3/MinIO**
3.  Разбивать видео на чанки
4.  Загружать чанки обратно в **S3**
5.  Отправлять события прогресса в **Kafka**
6.  Хранить состояние обработки в **Redis**
7.  Предоставлять API для получения статусов обработки

------------------------------------------------------------------------

## Ограничения MVP

| Параметр                  | Значение                                       |
|:--------------------------|:-----------------------------------------------|
| Формат видео              | только **MP4**                                 |
| Максимальный размер файла | **500MB (по умолчанию)**                       |
| Тип фрагментации          | **по времени**                                 |
|Размер чанка| приходит **в Kafka сообщении** (или 30 секунд) |
|Хранение состояния| **Redis**                                      |
|История статусов| **TTL** (по умолчниаю 24 часа)                 |

# 3. Основные архитектурные принципы

## Максимальная производительность

Ключевые решения:

-   **FFmpeg без перекодирования**
-   **Chunk upload сразу после появления**
-   **Удаление локальных файлов после загрузки**
-   **Параллельная обработка файлов**
-   **Параллельная загрузка чанков**

------------------------------------------------------------------------

## Асинхронная архитектура

Все операции выполняются асинхронно:

-   Kafka consumer
-   S3 download/upload
-   Redis
-   subprocess ffmpeg

------------------------------------------------------------------------

## Event‑driven pipeline

Pipeline основан на событиях.

    Kafka job event
          ↓
    video processing
          ↓
    Kafka progress events

------------------------------------------------------------------------

# 5. Поток обработки видео

    Kafka message
          │
          ▼
    HEAD request (S3)
    проверка размера
          │
          ▼
    download video
    S3 → local tmp
          │
          ▼
    ffprobe
    получение duration
          │
          ▼
    ffmpeg fragmentation
          │
          ▼
    chunk created
          │
          ▼
    upload chunk → S3
          │
          ▼
    Kafka progress event
          │
          ▼
    delete local chunk

После завершения:

    manifest.json
    upload → S3
    Kafka completed event

# 6. Kafka сообщения

## Входящее сообщение (job)

``` json
{
    "job_id": "uuid",
    # Уникальный идентификатор задачи обработки.
    # Используется для:
    # - отслеживания прогресса
    # - хранения состояния в Redis
    # - корреляции Kafka событий

    "file_id": "uuid",
    # Идентификатор исходного файла.
    # Позволяет связать файл с последним job.
    # Redis mapping:
    # vf:file:{file_id} -> job_id

    "input": {
        "bucket": "raw",
        # Имя S3 / MinIO bucket, где хранится исходный файл.

        "key": "videos/a.mp4"
        # Путь к видео внутри bucket.
        # Полный путь:
        # s3://raw/videos/a.mp4
    },

    "output": {
        "bucket": "chunks",
        # Bucket, куда будут сохранены фрагменты видео.

        "prefix": "videos/a/"
        # Префикс (директория) для сохранения чанков.
        # Пример результата:
        # videos/a/chunk_000000.mp4
        # videos/a/chunk_000001.mp4
    },

    "chunking": {
        "type": "time",
        # Тип фрагментации.
        # В MVP поддерживается:
        # "time" — разбиение по времени.
        #
        # В будущем:
        # "frame"
        # "size"
        # "custom_time"

        "seconds": 10,
        # Размер одного чанка в секундах.
        # Используется в FFmpeg:
        # -segment_time 10
        #
        # Например:
        # video = 120 секунд
        # seconds = 10
        # → получится ~12 чанков.

        "mode": "fast_keyframe_aligned"
        # Режим фрагментации.
        #
        # fast_keyframe_aligned (MVP):
        # - используется ffmpeg -c copy
        # - нет перекодирования
        # - максимально высокая скорость
        # - разрез происходит по keyframes
    },

    "limits": {
        "max_bytes": 524288000
        # Максимальный размер входного файла.
        #
        # Проверяется через S3 HEAD request
        # ДО скачивания файла.
        #
        # Default:
        # 500MB
    },

    "state_ttl_s": 86400
    # TTL состояния job в Redis.
    #
    # Используется для ключей:
    # vf:job:{job_id}
    # vf:file:{file_id}
    #
    # Значение:
    # 86400 секунд = 24 часа
}
```

------------------------------------------------------------------------

## Progress event

Отправляется **на каждый чанк**.

``` json
{
    "job_id": "uuid",  
    # Уникальный идентификатор задачи обработки видео.
    # Используется для отслеживания обработки и хранения состояния в Redis.
    # Соответствует ключу Redis: vf:job:{job_id}

    "file_id": "uuid",  
    # Идентификатор исходного видеофайла.
    # Позволяет связать файл с последней задачей обработки.
    # Используется в Redis mapping: vf:file:{file_id} -> job_id

    "status": "chunk_uploaded",
    # Текущий статус обработки.
    # Возможные значения:
    #   started         — обработка началась
    #   chunk_uploaded  — очередной чанк успешно загружен в S3
    #   completed       — обработка завершена
    #   failed          — обработка завершилась с ошибкой

    "chunk_index": 7,
    # Индекс обработанного чанка (начинается с 0).
    # Используется для отслеживания прогресса и порядка чанков.

    "chunk_key": "videos/a/chunk_00007.mp4",
    # Путь к чанку в S3 / MinIO.
    # Формируется как:
    #   {output.prefix}/chunk_{index}.mp4
    # Пример полного пути:
    #   s3://chunks/videos/a/chunk_00007.mp4

    "chunks_done": 8,
    # Количество чанков, которые уже успешно обработаны и загружены в S3.

    "chunks_total_estimate": 42,
    # Оценочное общее количество чанков.
    # Рассчитывается через:
    #   duration_video / chunk_seconds
    # Используется для отображения прогресса обработки.

    "ts": "2026-03-05T12:34:56Z"
    # Timestamp события в формате ISO 8601 (UTC).
    # Показывает момент публикации события в Kafka.
}
```

------------------------------------------------------------------------

## Финальное событие

``` json
{
    "job_id": "uuid",
    # Уникальный идентификатор задачи обработки.
    # Позволяет downstream сервисам понять,
    # какая именно задача завершилась.

    "file_id": "uuid",
    # Идентификатор исходного видеофайла.
    # Используется для связывания результата обработки
    # с исходным файлом.

    "status": "completed",
    # Финальный статус обработки.
    #
    # Возможные значения:
    # completed — обработка завершена успешно
    # failed    — обработка завершилась с ошибкой

    "chunks_total": 42,
    # Общее количество созданных чанков.
    #
    # Это фактическое значение,
    # в отличие от chunks_total_estimate,
    # которое рассчитывается заранее через ffprobe.

    "manifest_key": "videos/a/manifest.json",
    # Путь к manifest.json в S3.
    #
    # Manifest содержит информацию о всех чанках,
    # например:
    # - список чанков
    # - параметры фрагментации
    # - метаданные видео
    #
    # Пример полного пути:
    # s3://chunks/videos/a/manifest.json

    "ts": "2026-03-05T12:40:10Z"
    # Timestamp события в формате ISO 8601 (UTC).
    # Показывает момент публикации события в Kafka.
}
```

# 9. Видео фрагментация

Используется **FFmpeg segment muxer**.

    ffmpeg -hide_banner -loglevel error \
    -i input.mp4 \
    -map 0 \
    -c copy \
    -f segment \
    -segment_time <seconds> \
    -reset_timestamps 1 \
    -segment_format mp4 \
    chunk_%06d.mp4

------------------------------------------------------------------------

## Почему это быстро

-   **нет перекодирования**
-   используется **stream copy**
-   режется **по keyframes**

Скорость:

  метод            скорость
  ---------------- ---------------------
  re-encode        \~0.5x realtime
  copy + segment   **20‑50x realtime**

# 10. Производительность

### Основные оптимизации

#### HEAD перед download

    S3 HEAD

Позволяет не скачивать слишком большие файлы.

------------------------------------------------------------------------

#### Ephemeral storage

Видео скачивается во временную директорию:

    /tmp/{job_id}

Это быстрее чем стримить напрямую из S3.

------------------------------------------------------------------------

#### Upload чанков сразу

    chunk created
        ↓
    upload
        ↓
    kafka progress
        ↓
    delete local file

------------------------------------------------------------------------

#### Параллельная обработка файлов

Ограничение:

    MAX_JOBS

------------------------------------------------------------------------

#### Параллельная загрузка чанков

Ограничение:

    MAX_UPLOAD_CONCURRENCY

# 13. Расширяемость архитектуры

В будущем возможно поддержка дополнительных фрагментаторов.

|Fragmenter| описание                                                                                                                           |
|-------|------------------------------------------------------------------------------------------------------------------------------------|
|TimeFragmenter| по времени (режет видео на равные интервалы времени, например, каждые 10 секунд))        (релизовано в MVP)                        |
|CustomTimeFragmenter| произвольные интервалы <br/>(режет по произвольным временным интервалам)                                                           |
|FrameFragmenter| по кадрам (режет по количеству кадров (например, каждые 300 кадров)                                                                |                    
|SizeFragmenter| по размеру (пытается получать чанки примерно целевого размера (например, ~25MB каждый))                                            |
|KeyframeFragmenter| по GOP (режет строго по ключевым кадрам / GOP (например, “каждый GOP отдельным чанком” или “ближайший keyframe к нужному времени”) |

------------------------------------------------------------------------
